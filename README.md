# SSR-PPT-SKILL

演示制作技能，采用通用的 Agent Skills（`SKILL.md`）格式，可用于 Codex、Claude Code、Cursor、Grok Build、Antigravity、DeepSeek Harness 等 agent：借助风格配方、版式原型、字体与中文排版、插画与图标素材、开放许可配图、成品示例图、逐页策划和实际渲染验收，做出好看、有记忆点、信息不减而图多字少的演示；支持公司模板、离线 HTML 和原生可编辑 PPTX。仅供能直接查看图片的模型使用。

名称保持 **SSR-PPT-SKILL**，技能名为 `ssr-ppt-skill`。调用方式见下文“使用”。

## SKILL 3 版本

这个仓库是 **SSR-PPT-SKILL-3**，从 [SSR-PPT-SKILL-2](https://github.com/EuronSSR-01/SSR-PPT-SKILL-2) 的 df04b20 起步；SKILL 2 和 [SSR-PPT-SKILL-1.5](https://github.com/EuronSSR-01/SSR-PPT-SKILL-1.5)（SKILL 2 第一版的原样副本）保持不变，可以对照使用。技能名仍是 `ssr-ppt-skill`，和 SKILL 2 装在同一个目录会互相替换，只装一份。

这一版的目标：让模型做出的演示更好看、图更多字更少；弱一些的模型有能照着做的完整例子，强一些的模型也能自由发挥。所有配方、原型、字体、插画都是样本，不是规定，清单会继续增加。

- **成品示例图库**：`assets/design-examples.html` 集中展示 176 页示例，全部是 `pptx_kit.py` 做成的原生 PPTX 经渲染得到的图，内容都是虚构的（版式、配方、字体、配图用“知野生鲜社区店升级”，改写用三个虚构机构）：
  - 版式原型 24 个、54 页：每个原型先说帮观众看懂什么，再给 2–3 种排法；新增 L23 物件标注、L24 便当格；
  - 改写 5 组、11 页：同一页改写前（文字）和改写后（信息不减、大部分画成图），套在三个虚构机构的模板里（第二轮新增，第三轮重做，见下）；
  - 风格配方 19 套、76 页：原有 13 套全部保留并重写，新增 R14 扁平插画叙事、R15 线描说明书、R16 便当格、R17 政企庄重、R18 手账笔记、R19 复古印刷；每套用同一份内容做封面、数据页、图片页，再加一页特色页；
  - 字体 28 页：20 页字样（共 26 款字体，同一句标题、同一段正文、同一组数字）、7 组搭配、数字字体对比；
  - 配图 7 页：找图怎么挑、照片处理、文字压图、裁切、插画换色、补画物体、图标用法。
  每页的代码在 `examples/gallery/`，可以照着改；`build.py` 能重新生成全部图片。
- **风格配方改写**：不再按行业分配（删去“管理层汇报 → 咨询风”之类的对应表，也删去“混搭最多两套”）；每套写清看起来什么样、怎么做、素材怎么处理、换内容怎么调、哪里容易难看，由模型按内容判断，可以组合。
- **插画素材库**：`assets/illustrations/` 有两种风格：扁平圆润 41 个（货车、冷藏车、仓库、叉车、货架、工厂、农田、门店、超市推车、医院、学校、银行卡、票据、印章、电脑、数据看板、团队、客服……），线描 8 个。给出主色和强调色就整体换色，多个物体能拼成一条地平线上的场景；README 写清怎么补画一个物体、怎么新建一种风格、怎么只为项目画。`pptx_kit` 的 `illustration()` 一行插入。
- **真的去找图**：`scripts/find_images.py` 搜 Openverse 和维基共享资源的开放许可照片，生成带编号的候选总览让模型看图挑选，下载时把作者、许可和来源追加进 `sources.md`。`scripts/image_fx.py` 统一处理照片（黑白、调色、双色调、压暗、圆角、圆形、颗粒）并生成柔光、点阵、半调底图。
- **字体**：每款字体有字样图、许可和实测的字符覆盖（例如站酷系列只有 6,763 个常用字、庆科黄油体的“7”像“1”、系统宋体的小数点间距怪）；“全套最多两个字体家族”改为起步建议；`scripts/font_coverage.py` 检查字体缺字，写明 PPTX 缺字时怎么办。
- **`pptx_kit.py` 新增**：原生折线图（线尾直接标值、标签可加底色）、自由多边形和折线、线性渐变（照片上的文字遮罩）、半透明、竖排文字、字距。
- **版面检查更准**：54pt 以上的展示字有意出血、同一句字错位叠印（阴影、复古错版）改为警告；竖排文字不再被当成孤字；不同文字的重叠、普通文字超出页面仍是错误。
- **保留不变**：开场两问、只供能看图的模型使用、事实与口径的门槛、逐页看两遍、WPS／PowerPoint 导出检查、编辑测试。

### 第二轮：图示优先 = 信息不减，换载体

用户用 DSH 按公司模板实测第一轮后指出：页面上的字少了，图却没多，感觉不到原来每页有那么多内容。用户给的方向是“原来十条信息里七条是字、三条是图，改完应该七条是图、三条是字”。原因有四个：技能把图示优先写成了“少字、解释放备注”，模型就删和移；版式示例为了看清构图每页只放三五条信息，模型照着这个密度做；模板任务没写可以用插画，只剩装饰性的小图标；字数提示把图旁的短标签也算进去，等于鼓励删信息。这一轮的改动：

- **定义**：图示优先改为“信息不减，换载体”。每页先从材料列出信息条目，逐条决定用图还是用字，策划稿写“信息 N 条：图 x · 文 y”，做完对照清单数一遍；少字靠画，不靠删，只删真正的重复。开场第二问的说明同步改写。
- **改写示例**：新增 C01–C05，每组一页常见的文字写法、一页同样信息大部分画成图，都在虚构公司模板里完成（第三轮已换成新的题材和模板，见下）；`imagery.md` 新增“把一页文字改成图”，列出计数、比例、流向、有无、地点各用什么画。
- **公司模板**：写明模板限制母版、字体、配色和固定元素，不限制图的多少；插画用模板主题色换色。
- **字数提示**：`preview.py` 的页面字数提示只统计成段文字（超过约 20 字的一行或一段），图旁的短标签和数字不算；提示语改为“先把信息画出来，不删条目”。报告同时列出总字数和成段文字字数。“标签＋短句”排成的格子脚本抓不到，`visual-review.md` 写明要看图发现。
- **事实与重复**：数字旁的说明必须出自材料里说这个数字的那一处，不把两句话拼成一句；同一页里同一个数字不反复出现；插画要和旁边的栏目一一对应。这三条加进 `SKILL.md`、逐页审阅和反模式。
- **修复**：`pptx_kit.line()` 画的线保留了主题样式引用，默认主题会给线加阴影，现在和形状一样去掉；`find_images.py` 连不上任何图源时直接说明“连不上”，不再提示“换个关键词”。

### 第三轮：示例不对应实测材料，字号不让步，交付前必检

用户用 DSH 按第二轮又做了两份（一份公司模板汇报、一份培训课件），并要求示例和文档不能对应用户实测用的模板和材料：实测反复用同一份材料，示例若是它的改写，模型就会照抄示例。第二轮的复核意见（GPT）也一并处理。这一轮的改动：

- **改写示例重做**：C01–C05 换成三个虚构机构（医院、学校、工厂）的题材，模板外框也换成三种（页眉色带、左侧竖条、顶部细条加页脚标志）；页面类型改为门诊时间、边角料去向、图书馆改造、开放日人数、设备方案。每组 A、B 页依据代码里同一份材料（`*_FACTS`），保留“约、预计、估算”、时间起点和条件。C04 增加 C 页：同样的数按多少排序，和按位置摆的 B 页对照，说明按要回答的问题选。C05 的空压机插画是为这个例子画的（`examples/gallery/art/`），演示“只为项目画”。文档里的例子改成通用说法，不再点名特定行业的物料。
- **措辞（GPT 复核）**：信息完整包括对象、时间起点、条件和“约、预计、估算、建议”这类状态；“图七字三”是偏好，条目清单照写，图和字的计数可选，不为凑数拆条目或加图标；20 字只是脚本粗分短标签和句子的界线；插画和栏目对应得上即可，不要求一栏一幅；只删没有作用的重复，标题和图都强调同一个数可以；数字和说明要指同一对象、指标、期间、单位和条件，口径不同的数字不画在同一把尺上。
- **字号下限**：`SKILL.md`、逐页审阅、反模式写明正文现场不小于 20px（15pt）、阅读不小于 18px、图旁标签不小于 16px（12pt），信息多不靠缩字。DSH 两份成品约六成文字小于 12pt，上一轮的示例本身也有八成多：改写示例和 9 页配方示例的标签已放大，`pptx_kit` 折线图的数值轴刻度不再小于 16px。
- **检查脚本**：`preview.py` 新增警告“正文小字多”（页眉页脚之间小于 16px 的字约 40 字以上且占三成以上，按页面宽度折算，PPTX 和 HTML 都查）；每页列出“字不少却没有一张图片、插画、图表或表格”的页，`--visual-first` 时作为提示。后者专门补“标签＋短句”格子页抓不到的缺口；用形状画的图脚本认不出，看图确认即可。
- **交付前必检**：`SKILL.md` 开头写明交付前必须做完第 5 节的检查；第 5 节给出一条完整的检查命令；交付回复要写渲染方式、报告位置、看图发现并改了什么，没做的写“未检查”。
- **模板任务**：写明“不套用其他风格配方、不覆盖公司字体”指配色、字体和版式风格，不等于不用插画、照片和图标。
- **构建**：完整重建某一节时，删掉已经不存在的旧示例图和清单条目。

未指定格式默认 HTML＋PPTX＋`planning.md`；仅要求一种格式、大纲、样稿或局部修改，就只完成约定范围。精确页数包含封面与结束页。

## 工作方式

建立需求与证据 → 大纲与策划稿 → 定义视觉方向 → 制作交付格式 → 实际预览验收 → 交付。

方向不明确时先做方向比较，再用代表页校准，最后推广到全套。视觉部分包括字体与中文排版、风格配方、构图原型、图标、配图与插画手法。HTML 播放器保留缩放、键盘／触屏翻页、逐步揭示、概览、备注、全屏、黑屏、网址页码与打印。


## 安装

把本仓库的 `ssr-ppt-skill` 文件夹放进 agent 读取技能的目录。下表是各 agent 文档列出的用户级目录（2026 年 10 月查阅，以各 agent 最新文档为准）：

| Agent | 用户级技能目录 | 说明 |
|---|---|---|
| Claude Code | `~/.claude/skills` | 项目级为 `<项目>/.claude/skills` |
| Codex | `$CODEX_HOME/skills`，未设置时为 `~/.codex/skills` | |
| Cursor | `~/.cursor/skills` 或 `~/.agents/skills` | 项目级为 `.cursor/skills` 或 `.agents/skills`；文档还写明兼容读取 `.claude/skills`、`.codex/skills` |
| Grok Build | `~/.grok/skills` | 也会读取 `~/.claude/skills` 和 `~/.agents/skills` |
| Antigravity（agy CLI） | `~/.gemini/antigravity-cli/skills` | 桌面应用与 IDE 为 `~/.gemini/config/skills`；项目级为 `<项目>/.agents/skills` |
| DeepSeek Harness（dsh） | `~/.dsh/skills` | 来自社区插件 dsh-skills-manager 的说明，未见官方文档；可能需要该插件才能加载 |

**同一个 agent 会读取多个目录时，只装一份**，否则可能出现重名技能。例如已装到 `~/.claude/skills` 时，Grok Build 已能读到，不必再装到 `~/.grok/skills`。

用仓库自带的安装脚本（只依赖 Python 标准库），`--list` 会显示各目标路径与安装状态：

```bash
git clone https://github.com/EuronSSR-01/SSR-PPT-SKILL-3.git
cd SSR-PPT-SKILL-3
python install.py --list
python install.py --agent claude --agent agy           # 按需选择，可重复
python install.py --agent cursor --project /path/to/repo   # 装到某个项目的 .agents/skills
```

可选的 `--agent` 有 `claude`、`codex`、`cursor`、`grok`、`agy`、`agy-app`、`agents`（通用的 `~/.agents/skills`）和 `dsh`。目标已存在时脚本不会覆盖；加 `--force` 会先把旧版本移到技能目录旁边的 `skill-backups/` 中备份，再安装新版本。备份放在技能目录之外，避免 agent 把它当成第二个同名技能加载。

### 不支持技能的 agent

把下面这段放进项目的 `AGENTS.md`（或该 agent 读取的规则文件），并把路径改成实际位置：

```markdown
## 制作 PPT / 演示文稿
做 PPT、幻灯片、演示文稿或美化已有 PPT 时，先完整阅读
`<技能目录>/ssr-ppt-skill/SKILL.md` 并按其流程执行；需要时再读其中 references/ 下对应的文件，脚本在 scripts/ 下。
```

### 依赖

先运行环境自检，它只用 Python 标准库，会列出已有能力并给出建议路线：

```bash
python ssr-ppt-skill/scripts/doctor.py
```

按需安装，缺少时 Skill 会说明受影响的验收项：

```bash
python -m pip install fonttools brotli playwright pillow pymupdf python-pptx
```

- 浏览器：Playwright 会自动使用本机已安装的 Chrome 或 Edge；都没有时运行 `python -m playwright install chromium`。
- PPTX 渲染：Windows 上装了 WPS 或 PowerPoint 时用 `preview.py pptx --export wps`（或 `powerpoint`）；否则用 LibreOffice，或用 `--pdf` 传入由最终 PPTX 导出的 PDF。
- 新建 PPTX 默认用 python-pptx；已有 PptxGenJS 也可以用。

## 使用

调用方式因 agent 而异：Codex 写 `$ssr-ppt-skill`；Claude Code、Cursor、Grok Build 可以用 `/ssr-ppt-skill`；Antigravity 可以用 `/skills` 查看已加载的技能。各 agent 也会根据描述自动匹配，直接说“用 ssr-ppt-skill 做……”即可。

```text
用 ssr-ppt-skill，基于这些资料做 10 页管理层汇报，
交付离线 HTML、可编辑 PPTX 和策划稿。
需求已明确，后续自行判断，不再追问，完成后实际预览与编辑验证。
```

```text
用 ssr-ppt-skill，在这份公司 PPT 模板中制作 6 页方案。
仅交付 PPTX，保留母版、字体与品牌规范；遇到关键缺口可以逐个问我。
```

```text
用 ssr-ppt-skill，先整理大纲和逐页策划，暂不制作成品。
```

## 样例与验证

[双格式样例](ssr-ppt-skill/examples/dual-format/README.md) 共享一份虚构数据生成 4 页 HTML 和原生 PPTX，含长中文、分组流程、形状矩阵、统计图、原生表格和独立图片。它是可复现的有限路径，不是通用 HTML 转 PPTX 引擎。[示例图库](ssr-ppt-skill/examples/gallery/README.md) 的 176 页示例同样可以重新生成。

### SKILL 3 的验证（Claude Code／Windows，Chrome、LibreOffice 26.8）

- 回归测试 44 项（含 5 项浏览器测试）全部通过；新增 15 项覆盖插画库（每张图合规、索引一致、换色、场景比例、插入 PPTX）、图片处理、找图脚本（离线模拟接口）、`pptx_kit` 新功能、缺字检查、有意设计的三类警告，以及示例图和文档链接是否都存在。
- 165 页示例逐张看过：发现并修改的问题包括标题与单位换行、孤字、竖排轴标签读反、方案表行名重复、引线穿过别的模块、折线图网格线穿过标签、小倍数图刻度不到 9pt、学术图线尾标签重叠、庆科黄油体的“7”像“1”。版面检查最终结果：版式 54 页 0 错误、1 条警告（有意的编号出血）；配方 76 页 0 错误、10 条警告（全部是有意的出血、错版叠印和网格线穿过超大数字）；字体与配图 35 页 0 错误、0 警告。
- 双格式样例重新生成后严格检查通过：HTML、PPTX 版面都是 0 错误 0 警告，11 个编辑目标通过。
- `assets/design-examples.html` 在 Chrome 中按桌面和手机宽度打开：165 张图全部加载，没有横向溢出，搜索和大图查看可用，没有控制台错误。
- 安装脚本装到临时项目目录：391 个文件，哈希全部一致；`doctor.py` 报告插画库、示例和找图脚本。
- 照片都由 `find_images.py` 实际搜到、看过候选总览后选用，许可为 CC0、公有领域或 CC BY（已署名）。
- 尚未验证：示例只在 LibreOffice 中渲染，WPS／PowerPoint 的换行和字体可能不同；其他 agent 和模型用这一版做 PPT 的实际效果，需要在 DSH、Codex 等环境中对照。

## 脚本与边界

| 脚本 | 用途 |
|---|---|
| `install.py`（仓库根目录） | 把技能安装到各 agent 的技能目录 |
| `scripts/doctor.py` | 环境自检：已有能力与建议路线（只用标准库） |
| `scripts/pptx_kit.py` | python-pptx 基础操作：画布坐标、中西文字体、字距与竖排、无阴影形状、多边形、渐变与半透明、图标（原生形状）、插画与 SVG、单系列高亮条形图、折线图、无样式表格、裁切图片 |
| `assets/icons/` | 127 个 Lucide 线性图标（ISC 许可），`INDEX.md` 列出名称与中文含义 |
| `assets/illustrations/` | 物体与场景插画：扁平圆润 41 个、线描 8 个，可整体换色；README 写清怎么补画和新建风格 |
| `scripts/illustrations.py` | 插画列表、换色导出、拼场景、总览图、`check` 检查新画的图 |
| `scripts/find_images.py` | 搜开放许可照片（Openverse、维基共享资源），候选总览、下载并记录来源与署名 |
| `scripts/image_fx.py` | 照片处理（黑白、调色、双色调、压暗、圆角、圆形）与生成底图（颗粒、柔光、点阵、半调） |
| `scripts/font_coverage.py` | 检查字体能否显示 PPTX／HTML／文本里的每个字 |
| `assets/design-examples.html` | 176 页成品示例总览（版式、改写、配方、字体、配图）；`examples/gallery/` 是生成它们的代码 |
| `scripts/embed_fonts.py` | HTML 字体子集化、内联及缺字报告；嵌入前核许可 |
| `scripts/preview.py html` | 离线浏览、图片解码、字体加载、键盘、逐页截图、打印与版面检查；`--zoom` 放大局部；每页正文字数（括号里是成段文字），`--visual-first` 时提示长段落和成段文字多的页 |
| `scripts/preview.py pptx` | `--export wps／powerpoint` 由目标软件导出 PDF，或 LibreOffice 渲染，或 `--pdf` 传入 PDF；版面检查（孤字、文字跑出卡片、线条穿字、内容区偏一侧等）、对象与所有主题字体清单；指定对象编辑与重开，按类型汇总；`--zoom` 放大局部；每页正文字数（括号里是成段文字），`--visual-first` 时提示长段落和成段文字多的页（不需要渲染） |
| `scripts/preview.py sheet / compare` | 总览、灰度／模糊图与方向对照 |
| `scripts/set_theme_fonts.py` | 指定主题的字体修复；多主题要求明确选择范围 |

`--strict` 只要求脚本覆盖的必需自动检查通过，不能代替看图与目标应用测试。PPTX 编辑用 `--edit-test`，关键目标用 `--edit-targets` JSON 指定，详见 [对象合同与验证](ssr-ppt-skill/references/pptx.md)。

这是技能指令、播放器与辅助脚本，不包含 Office。图标是原生形状，可改颜色和尺寸；照片和 SVG 插画是独立图片，插画内部要改时编辑 SVG 源文件后重新生成；文字与数据图的编辑能力另测。复杂网页效果无需逐像素复刻，整页截图不算可编辑 PPTX。字体可用性、嵌入和分发依工具与授权处理。

复用已有工具链，默认当前智能体执行。Web Brain／Inner Web Brain 仅在用户为当前任务明确要求时使用。缺少必需能力时说明阶段成果和未完成项。
