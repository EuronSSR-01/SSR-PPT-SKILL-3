# 方向探索、代表页校准与审美验收

新建或美化演示时使用，与内容、交互及原生可编辑性检查一起执行。审阅对象是实际渲染后的页面图像；代码、对象清单和评分只提供辅助信息。看图指主模型直接查看最终渲染页面，生成了截图、写了“已查看”、OCR 或自动检查通过都不算看过图。截图、放大图、总览图和测试图可用本 Skill 的 `scripts/preview.py` 生成（见文末）。

## 先发散：比较两到三个方向

大约 6 页以上的新建或整体美化任务，在批量制作前先做方向比较：

1. 取封面和一个最能代表全套的关键页（通常是核心结论页或主要数据页）。
2. 为它们做 2–3 个**明显不同**的方向：不同配方（先在 [`assets/design-examples.html`](../assets/design-examples.html) 里比较气质），或同一配方下不同的构图、尺度与素材策略（照片／插画／纯排版）。只换配色不算不同方向。
3. 用真实内容快速制作并渲染，把同一页的各个方向并排放在一张对比图中查看。
4. 按下文的“出彩检查”和受众场景评判，选定一个方向或融合，把取舍理由写进策划稿。

5 页以内的短演示可以只比较两个封面方向。用户明确要求先看样稿时，把这些方向交给用户选择并止于此；否则自主选定后继续，不增加确认关卡。用户指定了模板或明确风格时跳过这一步。用户要“另做一版不用模板的”，也按这一节做出明显不同的方向，不是把模板版换个颜色。

## 再收敛：代表页校准

选定方向后，完成少量能暴露设计问题的代表页：封面、典型内容页、数据或复杂信息页，按实际包含的页型选择。代表页使用真实内容和接近最终长度的文字，不能用短占位词或空白图框掩盖拥挤。检查最长标题、中文断行、素材裁剪、图标和密集信息是否都适合选定方向。双格式任务要渲染两种格式的关键代表页，不能只看 HTML 就假定 PPTX 相同。

代表页先确认版心：内容区的左右边界取自模板（版式与占位符）或明确的网格，左右边距相等，或分别对齐页眉的标题与标志；模板或已确定的视觉方案有侧栏、图片带或不对称网格时，按对应网格执行，并在策划稿写明依据。确认后再批量制作，避免把同一个偏移复制到每一页。

发现问题就修改构图或视觉规则，回写策划稿，再推广到全套。已有演示局部修改时，选受影响的页面校准。

## 看整套

把全部最终页面排成缩略总览：

- **缩略图测试**：每页缩到约 240px 宽时，焦点仍能一眼分辨。分辨不出就说明主次不够。
- **节奏**：能量起伏与策划一致；高潮页确实最突出；没有三页以上无理由的同构图同密度。
- **一致性**：字体、色彩角色、对齐位置、图标风格与形状语言全套统一；母题出现在计划的位置。
- **版心**：各页内容区的左右边界是否一致且讲得通。每页都偏向同一侧，看起来“统一”，其实是同一个错误被复制了。
- **重复**：同一句话、同一组数字是否在多页反复出现（小结页回顾除外）。

总览只用来看节奏和一致性，不能用来判断小字是否可读。

## 逐页审阅：看两遍

**第一遍，完整尺寸的整页**，在实际演示尺寸下检查阅读效果：

| 检查项 | 观察依据 | 常见修正 |
|---|---|---|
| 焦点 | 第一眼能找到主题或主要证据，重要性与视觉面积相符 | 重排主次、缩短标题、放大关键图形、弱化竞争元素 |
| 层级与阅读顺序 | 标题、证据、解释和口径容易区分，视线不用来回跳 | 拉开字号与字重，调整分组和标注位置 |
| 版心与对齐 | 内容区左右边界与模板或页眉对齐，同类元素共用对齐线 | 按模板版式或网格重设内容区，统一边距 |
| 构图与留白 | 挂在网格上，主体比例合适，留白有方向，没有意外空洞 | 改变元素面积和位置，调整文本框内边距 |
| 信息量 | 对照策划稿的条目清单：页面上的信息一条不少，对象、时间起点、条件和“约、预计、估算、建议”这些限定也都在；图示优先时大部分条目由图承载，而不是被删掉或挪进备注。页面看起来空、信息比材料少，是不合格 | 把缺的条目和限定补回来，能画的画出来（插画、图标加短标签、点阵、比例条、时间条、箭头、图表） |
| 文字量 | 文字只留结论、关键数字、短标签和必要条件；没有大段说明；没有起不到作用的重复（标题和图可以强调同一个数，正文、注释、方框不再复述） | 把段落里的信息画出来，删重复，解释移到备注 |
| 字号 | 正文、图旁标签和图表标注达到 [typography.md](typography.md) 字号阶梯的下限；信息多不是缩字的理由 | 调整信息组织、拆页、合并重复，或换更省地方的画法 |
| 图片与图标 | 策划里要配图的页确实有图；图片主体清楚、裁剪自然、调色统一；插画风格统一、比例自然，看得出每幅对应哪一栏或哪一项（不要求一栏一幅）；图标贴切、风格与线宽统一；图里没有塞满文字 | 去找、去画（[imagery.md](imagery.md)），更换或重新裁剪素材，把插画挪到它说明的内容旁，统一图标，把图中文字移到图旁 |
| 事实 | 数字和旁边的说明与材料中的对象、指标、单位、期间和条件对应；没有把无关的数字、主体或效果拼成新的关系；放在同一把尺上比的数字口径可比，期间、状态和条件标明了；“约、预计、估算”等限定还在；模板示例文字（部门名、日期）没有被当成材料 | 改回材料原话；口径不可比的分开展示或按材料换算；把丢掉的限定补回图旁 |
| 中文与数据 | 断行自然，正文与标注可读，数字单位完整，图表比例准确 | 重排文字，调整图表与直接标注，核对实际字体 |
| 图形含义 | 箭头、连线、分组和数量图形表达的关系与材料一致 | 改图或改标题，不用脚注去否定图的主关系 |
| 反模式 | 对照 [anti-patterns.md](anti-patterns.md) 没有无理由的命中 | 按清单中的“改为”修改 |
| 版式适配 | 版式服务于内容：没有为套用配方或原型而凑内容、删内容或扭曲内容 | 修改原型或改为自定构图 |
| 使用场景 | 现场讲述能扫读，独立阅读能理解，模板要求得到保留 | 调整密度与解释位置，不擅自删除必需信息 |

**第二遍，放大的局部**（`--zoom` 生成的四个象限）：逐个象限看文字是否跑出卡片或底框、末行或强制换行前只剩一个字、行首标点、数字与单位断开、线条穿过文字、图标与文字是否对齐、图片边缘与裁切。这些细节在整页图上很容易漏看。

记录写发现的问题、所做修改和复查结果；没问题的页简记看了什么，不能只写“通过”，也不能写图里看不到的结论。

## 出彩检查

“没有重叠”“看起来整齐”只说明没有错误。以下检查判断是否足够好：

- **去品牌测试**：遮掉 logo、公司名和标题文字，这套页面能否和通用模板或常见的 AI 生成演示区分开？不能就回到视觉定调，加强母题、尺度、图片和图标。
- **截图测试**：是否至少有 1–3 页值得单独截图分享？高潮页做不到时，优先投入这些页面。
- **模糊测试**：把页面模糊到看不清字，剩下的最显眼的形状是否正是策划的焦点？
- **灰度测试**：去色后层级是否仍然成立，强调是否仍能分辨？做不到就说明过度依赖颜色。
- **精修**：
  - 边距与对齐用像素核对；大字和引号按视觉边缘做光学对齐。
  - 没有孤字和行首标点；数字与单位不断开。
  - 全套标题位置一致；页码、来源等小字的位置与样式统一。

改进优先改尺度、构图、素材和文字质量，而不是加阴影、渐变和装饰。圆角、渐变、居中、阴影本身不是错误：配方需要（例如 R9 的大圆角、R11 的背景柔光、R8 的居中对称）并且全套统一时照用；要改的是没有理由、随手加上的装饰。

公司模板任务不做去品牌测试，改为检查模板之内的精致度：是否对齐模板的版心和网格，层级是否比原稿清楚，图表与表格是否去掉了默认样式，图标是否让表格和卡片更好认；图示优先时，信息是否和原稿一样多、是否大部分由插画、图标和示意图承载，而不是只剩几行字和装饰图标。

## 修复与停止

在私有构建目录简短记录页码、观察到的问题、调整和复查结果。优先处理影响理解、阅读、事实或编辑的问题，再处理不够出彩的问题。

修复后重新导出并查看受影响页；全局字体、配色或间距规则改变时检查全套。HTML 和最终 PPTX 分别渲染验收。两者有视觉差异可以接受，但重要内容、焦点和编辑要求不能丢失；PPTX 以重新读取最终导出文件后的图像为准。

同时满足以下条件时完成：

1. 内容与事实正确，实际渲染可读，没有尚未解决的具体缺陷（包括版面检查的错误，以及看图确认过的警告）。
2. 没有无理由的反模式命中。
3. 高潮页达到策划的冲击力，并通过去品牌测试（公司模板任务看模板内的精致度）。
4. 节奏与一致性符合策划。

确实受能力、素材或时间限制而达不到出彩标准时，说明具体差距和原因，不用模型评分掩盖。审美记录留在构建目录，不额外打包成用户未要求的报告。

## 预览工具

`scripts/preview.py` 依赖 Pillow；HTML 还需要 Python 的 Playwright（使用已安装的 Chrome / Edge 或 Playwright 自带的 Chromium）；PPTX 需要 PyMuPDF，以及 LibreOffice 或 Windows 上的 WPS／PowerPoint：

```bash
# HTML：逐页截图（完全揭示状态）、放大局部、记录控制台与外部请求、小视口截图、打印 PDF 页数，并生成总览
python scripts/preview.py html build/index.html --out build/review/html --zoom --visual-first

# PPTX：由 WPS 导出 PDF 后逐页出图（没有 WPS／PowerPoint 时去掉 --export，改用 LibreOffice），做编辑测试
python scripts/preview.py pptx build/deck.pptx --out build/review/pptx --export wps --zoom --edit-test --visual-first

# 已有由最终 PPTX 导出的 PDF 时
python scripts/preview.py pptx build/deck.pptx --out build/review/pptx --pdf build/deck.pdf --zoom

# 任意图片：生成总览、灰度版与模糊版
python scripts/preview.py sheet build/review/html/slides --out build/review/html/sheet.png

# 方向比较：把多张图片并排放在一张对比图中
python scripts/preview.py compare a/01.png b/01.png c/01.png --out build/review/cover-compare.png
```

脚本生成逐页 PNG（`slides/`）、放大局部（`zoom/`）、总览与灰度／模糊图、版面检查标注图（`layout/`）、`report.json` 和编辑测试副本。生成的 PNG 要实际打开查看。

版面检查：

- 错误（必须修复）：普通字号的文字超出页面、不同的文字互相重叠；HTML 另查被溢出隐藏的容器裁掉的文字。
- 警告（逐条看图确认，有意的写明理由）：一行只剩一个字（含强制换行前的单字；竖排文字不算）、文字从卡片或底框里跑出来、线条穿过文字、至少 3 页的内容区偏向同一侧（左右边距不等）、正文小字多（页眉页脚之间小于 16px 即 12pt 的字有约 40 字以上、且占三成以上）、单个字号小于 12px（9pt）、疑似占位文字；HTML 另查对比度。小字警告是按字号、位置和数量筛出的复查线索，脚本分不出正文和来源：看图确认报的是什么。重要正文或图表标注确实过小，就放大、拆页或改画法；报的是来源、页码、脚注或照片署名，且符合 [typography.md](typography.md) 对这些内容的规定，可以保留，记录位置和理由。不能用一句“有意设计”统一豁免过小的正文。
- 有意的设计会以警告出现，确认后保留：54pt 以上的展示字从页边裁出（超大编号、海报字，HTML 用 `data-bleed` 标明），同一句文字错位叠印两遍（阴影、复古错版），网格线有意穿过超大数字。
- 检查只看几何关系，抓不到构图、含义和裁切质量。WPS／PowerPoint 与 LibreOffice 的换行可能不同，以目标软件导出的结果为准。

两个命令都列出每页正文字数（不含标题、表格和页脚区），括号里是其中成段文字的字数：超过约 20 字的一行或一段算成段，这只是脚本粗分短标签和句子的界线，不是写作规则；图旁的短标签和数字不算。还列出字不少（约 100 字以上）却没有一张图片、插画、图表或表格的页（不算页眉页脚里的标志和小图标）。加 `--visual-first` 时，脚本指出超过约 60 字的段落或文字卡片、成段文字超过约 150 字的页面，以及上面这种没有图的页面。这是复查线索，不算通过或失败：逐条处理——先把其中能画的信息画出来，再删重复、把解释移到备注；确需保留的写明是哪部分、为什么。“没有图”只是说脚本没识别到图片、图表等对象：用原生形状画的点阵、比例条、流程和示意分布同样有效，看图确认后写明即可；反过来，识别到图片也不等于图示充分，要看它是否帮观众认出对象、比较数量或理解关系。不为消掉提示删信息条目或必要条件、缩小字号、把文字做成图片，或添加装饰图片。字数是近似阅读量（汉字计 1，英文单词和数字计 2），不是合格线：信息画进图里以后，页面上可以有不少短标签；没有提示的页面也要看图，并对照条目清单确认信息没有变少。“标签＋短句”排成的格子每格都短，段落提示抓不到，常常只在“没有图”这一条上露出来：格子里看得见的东西、数量和流向，仍应画出来。

编辑测试的摘要按对象类型列出实际测试的目标（例如“文字 12、图片 2；本文件没有原生图表和表格”），验收记录照此填写。报告中的状态：

| 状态 | 意义 |
|---|---|
| passed／通过 | 执行并取得证据，只在报告覆盖范围内成立 |
| failed／失败 | 与要求不符，修复后重测 |
| not_run／未执行 | 尚未做或被跳过 |
| unsupported／工具不支持 | 当前方法不能覆盖，需换方法或说明限制 |
| not_applicable／不适用 | 本任务没有此要求，记录原因 |

`--strict` 只汇总脚本覆盖的自动检查；`manual_review` 保持未执行，由 Agent 在策划或验收记录中补实际看图与操作证据，不篡改自动结果。只有确实在 WPS 或 PowerPoint 中打开和操作过，才能报告实机验证；`--export` 只说明 PDF 由该软件导出，LibreOffice 渲染要如实报告为 LibreOffice。
