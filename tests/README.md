# 维护验证

仅用于修改技能和辅助脚本后的回归，不要求 Agent 每次制作 PPT 都跑全套维护测试。全部夹具为合成数据；结果写临时目录或已忽略的 .build，不提交用户材料和本地报告。

## 命令

```bash
python -m unittest discover -s tests -v
```

共 47 项（`test_validation.py`、`test_html.py`、`test_skill3.py`）。不设置浏览器时运行 42 项库层测试（LibreOffice 渲染测试在未安装时跳过，读取 PDF 的测试在没有 PyMuPDF 时跳过），5 项浏览器测试显式跳过。要验证浏览器行为，在可启动本机浏览器的环境中设置：

```powershell
$env:SSR_TEST_BROWSER = 'chrome'
python -m unittest discover -s tests -v
```

POSIX 使用 `SSR_TEST_BROWSER=chromium python -m unittest discover -s tests -v`。未运行／跳过不能说成通过。临时目录需可写；受限环境可为当前进程设置构建目录内的 TEMP／TMP／TMPDIR。

完整示例的生成、逐页预览和编辑目标命令见 [双格式样例](../ssr-ppt-skill/examples/dual-format/README.md)。在不同 agent 之间对比效果的固定任务与评分表见 [跨 agent 对比测试](cross-agent/README.md)。

## 行为检查与设计评估

维护脚本时同时验证成功样例与反例，例如“图表没改但仍存在”“表格原先有勾号”“分组内部未修改”“图型不支持”“内联图片损坏”；模板还要检查多个母版／主题、备注和链接。教学样例解释方法，独立材料检查迁移效果。

按入口和按需参考，维护时检查这些真实请求分流：已选自主模式、允许逐个询问、开场两问只问未明确的项、自主模式未选表达方式时按图示优先、图文均可不被强制图示化、公司模板只改局部、只要大纲、仅 HTML／仅 PPTX、不可比较／状态不同的数据、自绘矩阵与原生统计图的不同编辑要求。不能靠匹配标题或关键词证明决策正确。

比较新版前后时固定任务、素材、工具和条件，观察信息完整、关系准确、阅读顺序、视觉与编辑负担；分别记录工程结果和设计观察。本次未进行多模型盲测，不据上述工程通过宣称普遍提升所有模型的审美水平。

补充完成三组新材料的双格式制作与实际看图，8 个指定编辑目标通过。材料、观察、修订与未验证项见 [新材料检查记录](design-review.md)。它是同一 Agent 对新材料的执行与审查，没有旧版对照或独立评审人，不能作为跨模型效果结论。
